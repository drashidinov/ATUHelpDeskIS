# Накладки в расписании (АТУ)

Отдельный инструмент: находит накладки (конфликты) в расписании занятий —
когда одна аудитория или один преподаватель заняты в двух разных занятиях
одновременно. Изначально вырос из проекта техподдержки компклассов
(ATUHelpDeskIS, ветка main), но не связан с ним по назначению — это
самостоятельная задача проверки корректности расписания, а не вызова
специалиста. Поэтому вынесен в отдельную ветку.

## Структура

- `app/index.html` — standalone-страница, показывает две группы накладок:
  - **По аудиториям** — два разных занятия с пересекающимся временем в одной
    аудитории.
  - **По преподавателям** — один и тот же преподаватель в двух разных
    аудиториях с пересекающимся временем.
  Расписание встроено прямо в файл (см. `data/schedule_final.json`), поэтому
  открывается локально без сервера — просто как HTML-файл в браузере.
- `data/rooms_meta.json` — список 44 аудиторий-компьютерных классов техподдержки
  (корпуса 2Б, 2C, ГУК), с адресами корпусов. Сейчас накладки считаются только
  по этим аудиториям — при необходимости расширить на все аудитории вуза,
  нужен полный парсинг всего расписания (см. ограничения ниже).
- `data/schedule_final.json` — записи занятий для этих аудиторий (день недели,
  время, группа, текст занятия, эвристически извлечённое ФИО преподавателя).
  Источник — расписание бакалавриата (1-4 курс), магистратуры (1-2 курс),
  докторантуры и ТИПО, на весь академический период.
- `data/rooms_extracted_all_mentions.csv` — все уникальные варианты обозначения
  аудиторий, найденные во всех расписаниях (для справки).
- `scripts/rooms.py` — список целевых аудиторий + нормализация/распознавание
  номера аудитории в свободном тексте расписания (учитывает оба варианта
  записи корпуса: с цифрой «404-2С» и сокращённо «404-С»).
- `scripts/parse_schedules.py` — парсер: читает .xlsx расписания, находит
  ячейки с упоминанием целевых аудиторий, выгружает в `data/schedule_final.json`.
- `scripts/extract_teacher.py` — эвристика извлечения ФИО преподавателя из
  свободного текста ячейки. Точность не 100% — используется только для
  группировки возможных накладок по преподавателю, не как источник истины.

## Как считаются накладки

Два занятия пересекаются по времени в одной аудитории/у одного преподавателя →
кандидат в накладки. Чтобы не путать настоящую накладку с дублем одной и той
же записи (один и тот же предмет часто цитируется в нескольких файлах
расписания разных факультетов), тексты занятий сравниваются по схожести —
если похожи, считается одним и тем же занятием, а не конфликтом. Эвристика,
возможны единичные ложные срабатывания — финальную проверку делает человек.

Список пересчитывается заново при каждом открытии страницы — как только
обновится `data/schedule_final.json`, накладки пересчитаются автоматически,
без ручного шага.

## Ограничения текущей версии

- Считает только по 44 аудиториям-компклассам техподдержки, не по всему вузу.
  Для полного покрытия нужен отдельный парсинг всех аудиторий всех
  факультетов — текущий `parse_schedules.py` заточен под конкретный список
  целевых аудиторий.
- Эвристика извлечения ФИО преподавателя не покрывает все форматы ячеек
  (~83% успешного распознавания на реальных данных) — накладки по
  преподавателям, вероятно, занижены.
