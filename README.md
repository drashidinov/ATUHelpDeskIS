# ATU HelpDesk IS

Система техподдержки компьютерных классов АТУ:
1. Расписание занятий по аудитории (свободна / идёт занятие).
2. Вызов специалиста техподдержки из класса, с отображением на табло офиса.

## Структура

- `app/index.html` — терминал класса + табло ТП, один файл. Работает в двух режимах:
  - **Превью в Claude** — вызовы хранятся через `window.storage` (Claude Artifacts).
  - **Реальный хостинг** (ваш сервер) — `window.storage` недоступен, поэтому клиент
    сам переключается на запросы к `server/server.js` (`/api/calls`).
- `server/` — минимальный backend на Express: хранит вызовы в `server/data/calls.json`
  (JSON-файл, для начала достаточно; при росте — заменить на настоящую БД,
  сигнатуры `readCalls/writeCalls` менять не придётся) и отдаёт статику из `app/`.
- `data/rooms_meta.json` — список 44 аудиторий-компьютерных классов, закреплённых
  за техподдержкой (корпуса 2Б, 2C, ГУК), с адресами корпусов.
- `data/schedule_final.json` — записи занятий, извлечённые из расписания для этих
  аудиторий (день недели, время, группа, текст занятия).
- `data/rooms_extracted_all_mentions.csv` — все уникальные варианты обозначения
  аудиторий, найденные во всех расписаниях (для справки/будущей сверки).
- `scripts/rooms.py` — список целевых аудиторий + нормализация/распознавание
  номера аудитории в свободном тексте расписания. Учитывает оба варианта записи
  корпуса: с цифрой («404-2С») и сокращённо, без неё («404-С»).
- `scripts/parse_schedules.py` — парсер: читает .xlsx расписания, находит ячейки
  с упоминанием целевых аудиторий, выгружает в `data/schedule_final.json`.

## Запуск через Docker

```bash
docker compose up -d --build
```

Поднимет сервер на порту 3000 (терминал/табло + API), данные о вызовах сохраняются
в volume `helpdesk_data` между перезапусками контейнера.

## Запуск без Docker

```bash
cd server
npm install
npm start
```

Откройте `http://<адрес-сервера>:3000/` — по умолчанию открывается общий файл;
конкретный класс выбирается в выпадающем списке (или можно передать логику
выбора аудитории по URL/параметру при физическом монтаже терминала — сейчас
выбор сохраняется только в памяти вкладки).

## Следующие шаги для продакшна

- WebSocket/SSE для табло вместо поллинга каждые 3 сек.
- Авторизация специалистов на табло (кто принял вызов).
- Интеграция физической кнопки (ESP32) — дергает тот же `POST /api/calls`, что и
  веб-кнопка.
- Обновление `data/schedule_final.json` — сейчас статично, для реального
  использования нужно либо перезапускать `parse_schedules.py` при новом
  расписании, либо перевести хранение расписания в БД с загрузкой из xlsx через
  админку.
- Закрепление конкретной аудитории за конкретным терминалом (сейчас выбор из
  выпадающего списка — на реальном киоске лучше фиксировать через URL, например
  `/?room=404-2C`).
